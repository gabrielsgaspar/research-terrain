# Task: aggregate Base dos Dados tables in BigQuery; acquire homicides and annual population (build, idea 0007)

## Goal

Two raw datasets from Base dos Dados on BigQuery, and the small extension
of `terrain.bigquery` they need:

- `sim_homicides`: deaths by assault per year and municipality **of
  occurrence**, 1996-2024. They are counted in BigQuery from the SIM
  microdata (36.7 million rows), so only counts are downloaded.
- `ibge_population_annual`: population per municipality and year,
  1991-2025.

Campaign `research/campaigns/0007-gold-and-the-ballot/campaign.md`, step
s16. Steps s17 and s18 run the two acquires. Step s19 reuses the generic
acquirer for `tse_receipts` and builds `politics_panel`.

### `terrain.bigquery`: two optional keys

- `filters`: a list. Each item is one of:
  - `{column: c, prefix_between: [lo, hi], length: n}`, which gives
    `SUBSTR(c, 1, n) BETWEEN 'lo' AND 'hi'`;
  - `{column: c, in: [v1, ...]}`, which gives `c IN ('v1', ...)`.
  
  Each value must match `[A-Za-z0-9_]{1,20}`; anything else raises.
  Filters are added to the existing `WHERE` with `AND`.
- `aggregate`: `{group_by: [...], count: n, sums: [...]}`. It gives
  `SELECT <group_by>, COUNT(*) AS <n>[, SUM(CAST(<s> AS FLOAT64)) AS
  sum_<s>] ... GROUP BY <group_by> ORDER BY <group_by>`.
  - `columns` and `order_by` are not used when `aggregate` is present.
  - Every name goes through `_identifier`, so `cpf_cnpj*`, `nome*`,
    `geometria` and `telefone` are still refused.
  - The summary query counts the aggregated rows:
    `SELECT COUNT(*) AS n FROM (<the aggregate query without ORDER BY>)`.
- With neither key, `build_query` and `build_summary_query` return exactly
  today's strings. Test this against the `ibama_autos` and `inep_schools`
  catalog blocks.

### `terrain.basedosdados`

Query, type, write `<name>.parquet`, and write the manifest in a new dated
raw folder (write-once). Upload only after the checks pass:

- the row count matches the summary query;
- the rows are at least the block's `min_rows`.

The manifest records:

- the query text and the table;
- the row count;
- rows per `ano`.

"Unchanged" follows `terrain.inep`: same query, same count, same rows per
year means nothing is uploaded.

### Catalog entry `sim_homicides`

- `source`: "DATASUS, Sistema de Informações sobre Mortalidade (SIM), via
  Base dos Dados: basedosdados.br_ms_sim.microdados; deaths by assault
  (CID-10 X85-Y09) counted by year and municipality of occurrence".
- `licence`: "Base dos Dados lists 'desconhecida'; DATASUS publishes SIM as
  public data. Only municipality-year counts are stored."
- `gcs: data/raw/sim/homicides/`; `status: planned`.
- `bigquery:`
  - `endpoint` and `scope` as `inep_schools`;
  - no `page` key (the dataset page's address was not confirmed). The
    manifest's source `url` is then null, as `terrain.inep` already allows
    with `bq.get("page")`;
  - `table: basedosdados.br_ms_sim.microdados`, `location: US`,
    `maximum_bytes_billed: 50000000000`;
  - `states`: all 27 (AC ... TO, DF included); `years: [1996, 2024]`;
  - `filters: [{column: causa_basica, prefix_between: [X85, Y09], length: 3}]`;
  - `aggregate: {group_by: [ano, id_municipio_ocorrencia], count: n_obitos}`;
  - `min_rows: 50000`.
- `notes`:
  - The columns come from Base dos Dados' metadata (GraphQL API,
    2026-11-11): `ano`, `sigla_uf`, `id_municipio_ocorrencia` and
    `id_municipio_residencia` (7-digit IBGE codes), and `causa_basica`
    (CID-10). The table is partitioned by `ano` and `sigla_uf`.
  - Whether `sigla_uf` is the state of residence or of occurrence is
    unconfirmed; all 27 states are listed, so it does not matter.
  - CID-10 X85-Y09 is "agressões", the usual homicide definition; Y35-Y36
    (legal intervention) are left out.
  - The metadata's coverage to 2026 is implausible. The manifest records
    rows per year, and the final SIM data run to 2024.
  - Fallbacks:
    - `basedosdados.br_ms_sim.municipio_causa` counts by municipality of
      **residence**, not occurrence;
    - DATASUS' own `.dbc` files need a decompressor the project does not
      have.
  - Outcome data for both halves: it stays in raw, which no exploration
    account reads.

### Catalog entry `ibge_population_annual`

- `source`: "IBGE municipal population (estimates and census counts), via
  Base dos Dados: basedosdados.br_ibge_populacao.municipio".
- `licence`: "public (IBGE); Base dos Dados lists no licence".
- `gcs: data/raw/ibge/population_annual/`; `status: planned`.
- `bigquery:`
  - `table: basedosdados.br_ibge_populacao.municipio`;
  - `columns: [ano, sigla_uf, id_municipio, populacao]`;
  - `order_by: [ano, id_municipio]`;
  - all 27 states; `years: [1991, 2025]`; `min_rows: 150000`;
  - endpoint, scope, location and bytes as above.
- `notes`:
  - The columns come from Base dos Dados' metadata (2026-11-11). The table
    is partitioned by `ano`, `id_municipio` and `sigla_uf`.
  - Fallback: `basedosdados.br_ms_populacao.municipio`, 2000-2025, by age
    and sex.
