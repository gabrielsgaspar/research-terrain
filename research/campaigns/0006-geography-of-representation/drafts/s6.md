# Task: acquire INEP school facilities and the school catalogue (build, idea 0006)

## Goal

Two raw datasets for idea 0006. No phone number, email or personal name is
ever stored in either.

- `inep_schools`: school facilities by year, from Base dos Dados on
  BigQuery;
- `inep_school_catalogue`: one recent year of school names, addresses and
  postcodes from INEP's Censo Escolar microdata, with coordinates where
  INEP's school catalogue gives them.

Campaign `research/campaigns/0006-geography-of-representation/campaign.md`,
step s6. Steps s7 and s8 run the two acquires through `data-pipeline`. Step
s9 writes the match that reads the catalogue.

## Idea

Idea 0006 (`research/ideas/0006-geography-of-representation.md`), decision
0011. The data rules are in `AGENTS.md` ("Data", "Personal identifiers") and
decision 0003. `inep_schools` holds outcome data (facilities) for both
halves. It stays in raw, which no exploration account reads, and only
`place_outcomes` (step s14) reads it. The model for the BigQuery path is
`src/terrain/ibama.py` with `src/terrain/bigquery.py` (campaign 0004, step
s1). This is a **build** task: it may change exactly the files below.

### Rules that bind this code

- **No URL or raw folder in code** (`tests/test_acquire.py::test_no_url_or_dataset_folder_in_code`).
  Every URL, endpoint, scope and table id lives in the catalog.
- **Identifiers and contact data.** These are never selected, read, stored,
  logged or put in a manifest:
  - BigQuery: `telefone`, and any column starting with `nome` (refused by
    `bigquery._identifier`, unchanged);
  - microdata: `NU_DDD`, `NU_TELEFONE`, and any column whose name contains
    `EMAIL`. INEP's 2024 file has no email column.
  
  The school name (`NO_ENTIDADE`) is the name of a public building, not of
  a person. It is read from the microdata only.
- **Encodings:** every text read or write names its encoding.
- **Write-once raw:** new dated folder (`terrain.acquire._free_prefix`); the
  manifest is the last object created; nothing is uploaded until every check
  passes.
- **TLS for INEP.** `download.inep.gov.br` does not send its intermediate
  certificate, so the system trust store alone fails ("unable to get local
  issuer certificate"; checked 2026-11-10). No certificate is stored in the
  repository. At run time, before any request to INEP:
  1. Download the intermediate from its issuer's public address,
     `extra_ca_url` in the catalog (a DER file).
  2. Compute its SHA-256 and compare it with `extra_ca_sha256` in the
     catalog. A mismatch, or a failed download, fails the run before INEP
     is contacted.
  3. Build `ssl.create_default_context()` (the system trust store) and add
     the certificate with `load_verify_locations(cadata=<DER bytes>)`.
  4. Use that context with `urllib.request` for the INEP download, in
     `src/terrain/inep.py`; `terrain.http` is unchanged.
  
  Verification is never turned off and `ssl.VERIFY_X509_PARTIAL_CHAIN` is
  never set, so the chain must still end at a root the system trusts
  (GlobalSign Root R46). The downloaded certificate is kept in memory only.
  It is never written to the bucket, the manifest or a log. The manifest
  records only the URL and the fingerprint that matched.
- **Tests** never touch the network, GCS or BigQuery.

### `bigquery.py` changes

- `_where`: `years` may be absent or `null`; then the year clause is left
  out. `states` stays required.
- `build_summary_query`: a block may set `freshness_column` (for example
  `data_extracao`). When it is absent the query is
  `SELECT COUNT(*) AS n FROM ... WHERE ...`. The IBAMA entries gain
  `freshness_column: data_extracao` in this task's catalog change, so their
  query texts are unchanged. A test checks this.

- `gcs: data/raw/inep/schools/`; `status: planned`;
  `contract: data/contracts/inep_schools.md`.
- `bigquery:` block:
  - the endpoint and scope as `ibama_autos`;
  - `page: https://basedosdados.org/dataset/dae21af4-4b6a-42f4-b94a-4c2061ea9de5`;
  - `table: basedosdados.br_inep_censo_escolar.escola`; `location: US`;

  - `states`: the 27 states and DF (`AC, AL, AM, AP, BA, CE, DF, ES, GO, MA,

  - `years: [2007, 2024]`; `order_by: [ano, id_escola]`.
- `bigquery.columns`, exactly:
  - `ano`, `id_escola`, `id_municipio`, `sigla_uf`;
  - `rede` (STRING: "1" federal, "2" state, "3" municipal, "4" private);
  - `tipo_localizacao` (STRING: "1" urban, "2" rural);
  - the facilities: `agua_rede_publica`, `esgoto_rede_publica`,
    `energia_rede_publica`, `internet`, `biblioteca_sala_leitura`,
    `laboratorio_ciencias`, `laboratorio_informatica`, `quadra_esportes`;
  - accessibility: `dependencia_pne`, `acessibilidade_inexistente`.
- These facts come from Base dos Dados' model
  (`queries-basedosdados/models/br_inep_censo_escolar/`) and INEP's 2024
  dictionary, read on 2026-11-10. Put them in `notes`:
  - every facility column is INT64, 0 = no, 1 = yes;
  - `dependencia_pne` is collected 2007-2018 only;
  - `acessibilidade_inexistente` (1 = none of the accessibility items) is
    collected 2019-2024 only, after INEP's 2019 questionnaire change;
  - the other facility columns are collected 2007-2024;
  - the table has 4,272,656 rows for 2007-2025, is partitioned by `ano`,
    and `(ano, id_escola)` is unique.

`inep_school_catalogue`:

- `source`: "INEP, Microdados do Censo Escolar 2024; coordinates from
  INEP's Catálogo de Escolas via Base dos Dados:
  basedosdados.br_bd_diretorios_brasil.escola".
- `licence`: the same text as `inep_schools`.
- `gcs: data/raw/inep/catalogue/`; `status: planned`;
  `contract: data/contracts/inep_school_catalogue.md`.
- `microdata:` block:
  - `url: https://download.inep.gov.br/dados_abertos/microdados_censo_escolar_2024.zip`
    (33,829,396 bytes, Last-Modified 2026-07-08);
  - `member: "*/dados/microdados_ed_basica_2024.csv"` (217,925,280 bytes,
    426 columns, 215,545 rows);
  - `encoding: latin-1`, `delimiter: ";"`;
  - `extra_ca_url: http://secure.globalsign.com/cacert/rnpicpedugr46ovtlsca2025.crt`
    (the issuer address in INEP's certificate: "RNP ICPEdu GR46 OV TLS CA
    2025", issued by GlobalSign Root R46, valid until 2030-11-19);
  - `extra_ca_sha256: e10747d4da7bab09cba9952f019d3534cb9fba070bf13d8791b1699cd2ff59dd`
    (SHA-256 of the DER bytes, checked on 2026-11-10);
  - `columns:` `NU_ANO_CENSO, CO_ENTIDADE, NO_ENTIDADE, CO_MUNICIPIO, SG_UF,
    TP_DEPENDENCIA, TP_LOCALIZACAO, DS_ENDERECO, NU_ENDERECO, DS_COMPLEMENTO,
    NO_BAIRRO, CO_CEP`.
- `bigquery:` block, for coordinates only:
  - `table: basedosdados.br_bd_diretorios_brasil.escola`, with the endpoint,
    scope, location and cap as `inep_schools`;
  - `columns: [id_escola, id_municipio, sigla_uf, latitude, longitude]`

  - `states`: all 27; no `years`; `order_by: [id_escola]`.
- `notes`: the two sources. If INEP or its issuer changes the certificate,
  the fingerprint check fails by design, and a person updates
  `extra_ca_url` and `extra_ca_sha256`.

### Acquire `inep_schools`

- BigQuery path only, as in `ibama.py`: credentials, session, billing
  project from `GOOGLE_CLOUD_PROJECT`, paging, typing and the failure rules.
- Unchanged check: the summary query (`COUNT(*)`; no freshness column). If
  the latest manifest has the same query text and the same count, return
  `unchanged`.
- Store one Parquet, `inep_schools.parquet`, typed:
  - `ano` Int64;
  - `id_escola`, `id_municipio`, `sigla_uf`, `rede`, `tipo_localizacao`
    Utf8;
  - each facility column Int8, nulls kept.
  
  Values are stored as received, with no recoding. Size check: 2 GB.
- Manifest notes, values only: rows per year; for each facility column,
  the years in which it is entirely null; the distinct values of `rede` and
  `tipo_localizacao`.

### Acquire `inep_school_catalogue`

- Fetch and check the intermediate certificate (above), then download the
  zip with that context. Check that it is a zip with exactly one member
  matching `member`.
- Stream the member (Latin-1) to a temporary UTF-8 file in chunks. Read it
  with `pl.scan_csv(..., separator=";", infer_schema=False)`, selecting only
  the listed columns. Check that every listed column is in the header. The
  phone columns are never selected, and a test checks that their synthetic
  values reach no output.
- Run the BigQuery coordinates query. A failure there fails the run: the
  match needs to know which schools have coordinates.
- Store one Parquet, `inep_school_catalogue.parquet`, one row per
  `CO_ENTIDADE`. Columns:
  - `ano` (Int64), `id_escola` (Utf8, from `CO_ENTIDADE`), `nome_escola`
    (Utf8, from `NO_ENTIDADE`), `id_municipio` (Utf8, 7 digits), `sigla_uf`;
  - `rede` (Utf8, from `TP_DEPENDENCIA`), `tipo_localizacao` (Utf8);
  - `endereco`, `numero`, `complemento`, `bairro` (Utf8);
  - `cep` (Utf8, 8 digits with leading zeros, or null when not 1-8 digits);
  - `latitude`, `longitude` (Float64 from Base dos Dados, joined on
    `id_escola`; null when absent, 0, or outside latitude -34..6 and
    longitude -74..-28).
  
  The column `nome_escola` is a school's name. `bigquery._identifier`'s
  `nome` guard does not apply, because that guard is for BigQuery column
  names and this column comes from the microdata.
- Manifest notes, values only:
  - rows, and rows per state;
  - the share with a CEP and the share with coordinates;
  - the count of microdata rows with no coordinate row, and of coordinate
    rows with no microdata row;
  - the URL and fingerprint of the intermediate certificate used.
