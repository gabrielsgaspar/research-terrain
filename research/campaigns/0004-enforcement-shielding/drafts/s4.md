# Task: build cell_enforcement, IBAMA flora fines and embargoes per 1 km cell and year, split by half (build, idea 0005)

## Goal

A build that counts, for every Legal Amazon 1 km cell of `grid_cells` and
every year 2000-2025, the IBAMA flora fines (cancelled ones excluded) and
embargoes whose point lies inside their own municipality. It also writes a
municipality-by-year table of all and located records, for step s6's
coverage check. Outcome data are sealed like `cell_outcomes` (decision
0003). Exploration-half rows go to `data/derived/cell_enforcement/`;
confirmation-half rows go only to `sealed/outcomes/cell_enforcement/`,
which no explore code can read.

Campaign `research/campaigns/0004-enforcement-shielding/campaign.md`, step
s4. Step s5 runs it once through `data-pipeline` (`stage=build`); steps s6
and s8 read it.

### Inputs (by catalog name)

- `ibama_autos`: `ibama_autos.parquet` (contract
  `data/contracts/ibama_autos.md`). The columns used are `fonte`,
  `id_auto`, `data_auto`, `ano`, `id_municipio`, `latitude`, `longitude`,
  `tipo_infracao`, `indicador_cancelado` and `indicador_coordenada_valida`.
- `ibama_embargos`: `ibama_embargos.parquet`. The columns used are `fonte`,
  `id_embargo`, `data_embargo`, `ano`, `id_municipio`, `latitude`,
  `longitude` and `indicador_coordenada_valida`.
- `ibge_boundaries_2024`: `BR_Municipios_2024.zip`, polygons keyed by
  `CD_MUN`, SIRGAS 2000 degrees, read as `grid_cells` reads it
  (`data/contracts/grid_cells.md`, rule 3).
- `grid_cells`: `nome_1KM`, `cd_ibge`, `x_km`, `y_km` (5,029,081 cells, 773
  Legal Amazon municipalities).
- `data/derived/split/explore_municipalities.csv`, through
  `terrain.explore.EXPLORE_LIST`, as `cell_outcomes` reads it.

Every input's SHA-256 is checked against its manifest (`_fetch`).

### The rules

1. **Year.** `ano` is the calendar year of `data_auto` or `data_embargo`;
   if the date is null, the stored `ano`. Only 2000-2025 are kept.
2. **Legal Amazon.** A record counts only if `id_municipio` is a 7-digit
   code of a `grid_cells` municipality. Others are dropped. That is
   expected, since the states include non-Legal-Amazon parts of MA, and it
   is not an error.
3. **Cancelled fines are excluded.**
   - Normalise `indicador_cancelado`: strip, casefold, remove accents.
   - Cancelled: `sim`, `s`, `1`, `true`, `verdadeiro`, `cancelado`.
   - Not cancelled: `nao`, `n`, `0`, `false`, `falso`, the empty string and
     null.
   - Any other value stops the build (BuildError naming the value). The
     distinct values are in the s2 manifest notes, so the planner checks
     this set against them.
4. **Flora fines only.**
   - A fine is flora when `tipo_infracao`, normalised the same way, equals
     `flora`.
   - If no value in the input normalises to `flora`, the build stops.
   - Embargoes are not filtered by type: every embargo counts.
5. **Located.** A record is located when all of these hold:
   - `latitude` and `longitude` are finite;
   - the point (longitude, latitude), in degrees, lies inside or on the
     boundary of the `BR_Municipios_2024` polygon whose `CD_MUN` equals
     the record's `id_municipio` (shapely, `covers`);
   - the 1 km cell that contains the point is a `grid_cells` cell whose
     `cd_ibge` equals `id_municipio`. The point goes to Albers km with
     `terrain.grid`'s projection, and the cell is the floor of x and y,
     named `1KME<x>N<y>`.

   This check is ours and is the same for both sources.
   `indicador_coordenada_valida` is never used to decide.
6. **Half.** A row belongs to the exploration half if its `cd_ibge` is in
   the split list, otherwise to the confirmation half (as `cell_outcomes`,
   rule 2). Because a located record's cell has the record's own
   municipality, the cell table and the municipality table split the same
   way.

### Outputs (one file per year and half; `<y>` is 2000-2025)

- `cell_enforcement_<y>.parquet`: one row per cell with at least one
  located action in the year. Absent cells have zero. Columns:
  - `nome_1KM` (Utf8), `cd_ibge` (Utf8), `ano` (Int64)
  - `n_fines_flora` (Int64), `n_embargoes` (Int64)

  Sorted by `cd_ibge`, `nome_1KM`.
- `muni_enforcement_<y>.parquet`: one row per Legal Amazon municipality of
  the half, every municipality present even with zeros. Columns:
  - `cd_ibge`, `ano`
  - `n_fines_flora_all`, `n_fines_flora_located`
  - `n_embargoes_all`, `n_embargoes_located`

  "all" counts the records of rules 1-4 whatever their coordinates;
  "located" adds rule 5.

Paths:

- exploration half: `<derived><hash>/<file>`;
- confirmation half: `<sealed><hash>/<file>`.

Both come from the catalog entry, with the same `<hash>`. The hash is
`content_hash` of:

- the sorted input SHA-256s (both acquire Parquets, the boundaries zip, the
  grid Parquet);
- the split list's SHA-256 and the years;
- the source of `terrain/builds/cell_enforcement.py`, `terrain/grid.py`,
  `terrain/ibama.py` and any other `terrain` module the build imports to
  read or check its inputs (AGENTS.md, "Agents").

### Upload, manifest and what it may say

As `cell_outcomes`:

- Every file is written locally and checked first.
- Sealed files are uploaded first, create-only. The build never lists,
  reads or checks `sealed/`; an existing object stops it.
- Then the derived files, then the manifest, with `files` (derived) and
  `sealed_files`.
- A run whose derived manifest exists returns `unchanged`.

**The notes and every exception message give counts for the exploration
half only.** A pooled count minus the exploration count would reveal the
confirmation half's enforcement, so none is written. The notes hold:

- the source of each input (`fonte`);
- per year, for the exploration half, records dropped by reason: no date
  and no year; outside 2000-2025; municipality not Legal Amazon; no
  coordinates; outside own polygon; cell in another municipality or not
  in the grid;
- **when `fonte` is `basedosdados`**, one data-quality line for the
  exploration half, records with coordinates only: how often our rule 5
  check agrees with `indicador_coordenada_valida`. Normalise that field
  as in rule 3 (`sim`, `s`, `1`, `true` → valid; `nao`, `n`, `0`, `false`
  → not valid; null or other values reported separately). Give the
  shares agree, disagree and not comparable, and their counts. It is not
  a kill rule.

## Done when

1. A test builds a tiny world inside the test:
   - two municipality polygons in a zip shaped like `BR_Municipios_2024`;
   - a few `grid_cells` rows;
   - a split list with one municipality in each half;
   - synthetic `ibama_autos` and `ibama_embargos` Parquets in the contract
     schemas.

   It checks that the derived files hold only the exploration
   municipality, the sealed files only the other, and the counts in each
   are right.
2. Cases each way:
   - a cancelled fine (`Sim`) is dropped, an uncancelled one (`Não`)
     counts, and an unknown value (`talvez`) stops the build;
   - a `Flora` fine counts, a `Fauna` one does not, and an input with no
     flora value stops the build;
   - a point outside its own polygon is not located, and is still in
     `n_*_all`;
   - a point in its own polygon whose cell belongs to the neighbour is not
     located;
   - a point inside counts in the right cell;
   - a record outside 2000-2025 or outside the Legal Amazon is dropped.
3. `muni_enforcement_<y>` has every municipality of its half, zeros
   included, for every year 2000-2025.
4. With `fonte` = `basedosdados`, the notes carry the agreement line. With
   `fonte` = `ibama`, they do not. No note and no exception message holds
   a confirmation-half count: a test with a confirmation-half record that
   fails each check finds no number from it in the notes.
5. Changing the source of `terrain/ibama.py` or of the build changes the
   hash. An existing sealed object stops the build before any derived file
   is uploaded. A second run with the same inputs returns `unchanged`.
6. `data/contracts/cell_enforcement.md` documents every column, rule and
   check above.
7. `uv run ruff check .`, `uv run ruff format --check .` and `uv run pytest`
   pass, including `tests/test_split.py`.
