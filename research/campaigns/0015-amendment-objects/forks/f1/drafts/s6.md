# Task: What allied towns get, with the no-plan Pix line fitted in log_pc only (explore, idea 0013, fork of s5) (explore, fork f1 of campaign 0015)

## Goal

A new explore script, `explore/0013_objects_main_noplan_lin_f1.py`, on the exploration half. It repeats step s4's `explore/0013_objects_main.py` (campaign `research/campaigns/0015-amendment-objects/campaign.md`, draft `drafts/s4.md`) with one difference: the descriptive `no_plan` line under Pix groups is estimated by the linear `log_pc` fit only, and its Poisson fits are not run. Its `results.json` carries `first_stage.n_strong` and `estimates.finite` at the same paths as the parent, because the fork's run inherits step s5's kill rules unchanged.

## Idea

Idea 0013 (`research/ideas/0013-what-allies-get.md`). Step s5's run `research/explore-runs/0013/45061701322.md` was killed by k2 alone. The only non-finite value is `pix_groups.no_plan.poisson.C`: n_obs 0, with b, se and p null. The other no_plan Poisson fits are separated: B has b 19.8 on 119 rows, and pooled B+C has b 146. A Poisson premium is not identified for an outcome that is zero in nearly every deputy group. no_plan money is already part of `fungible` (`data/contracts/amendments_objects.md`), so the line is descriptive only. This is an **explore** task (label `explore`): it changes only the two files below.

## In scope

- `explore/0013_objects_main_noplan_lin_f1.py` (new).
- `tests/test_explore_objects_main_noplan_lin_f1.py` (new).

The script loads `explore/0013_objects_main.py` with `importlib.util.spec_from_file_location` (registered in `sys.modules`, as the parent loads `explore/0010_amendments_main.py`). It reuses that script's functions unchanged: reading, joining, window, fits, differences, Holm, composition, figures and the finiteness check. Wherever possible it overrides only the step that fits the `no_plan` Poisson line. It never edits the parent's file.

Rules that bind it, all as in the parent draft:
- exploration half only: `terrain.explore.exploration_municipalities(store, national=True)`, then `restrict` on `cd_ibge` right after each file is read;
- nothing in `sealed/`;
- the same data, columns, window (h read from `research/explore-runs/0010/44484340952.json`, with 5% as a check), estimators, scopes, seeds and draws.

`results.json` keys: exactly the parent's keys (s4 draft, "`results.json` keys"), with these differences:
- `pix_groups.no_plan.poisson` is absent;
- `pix_groups.no_plan.log_pc.<pooled_bc|B|C>` is present, as in the parent.

In particular the script writes:
- `first_stage.n_strong` (integer, 0 to 3, over visible, services and fungible, as in the parent) and `first_stage.f_cluster.<visible|services|fungible>`;
- `estimates.finite` (bool): true only if every estimate written is finite;
- `differences.*`, `declared.*`, `instruments.*`, `check_5pct.*`, `counts.*`, `window.*`, `composition.*`.

Figures: the parent's three PNGs, through `terrain.style` (`configure`, `save_png`), each under 400 KB and marked "exploration half, not a finding". `premium_by_group.png` shows visible, services and fungible only, because no_plan has no Poisson premium.

`summary.md`: as the parent's. It also has one line saying the no_plan line is linear only, and why: the Poisson fit in cycle C had no rows in the parent run.

## Out of scope

- Any change to the visible, services or fungible groups, to the instruments, to the declared estimates or Holm, to the window, models, scopes, draws or seeds, or to how `n_strong` and `estimates.finite` are computed.
- Specificity, Legado against regular, or classes on their own.
- The pre window, votes, the confirmation half.
- Any file other than the two above.

## What differs from the parent

Only the models fitted: the descriptive `pix_groups.no_plan` line is estimated by `log_pc` only, and its three Poisson fits (B, C, `pooled_bc`) are not run or written. Everything else is the parent's, through the parent's own functions.

## Done when

1. The script loads `explore/0013_objects_main.py` by importlib and calls `exploration_municipalities` and `restrict` (the repository's explore test passes for it).
2. On a synthetic panel and objects table built in the test, the script's `results.json` matches what the parent's functions give on the same tables. All keys and values match, except that `pix_groups.no_plan.poisson` is absent.
3. On a synthetic table where the no_plan outcome is zero in every cycle C row, `estimates.finite` is true, and `pix_groups.no_plan.log_pc.C` is written.
4. `first_stage.n_strong` is 3 on a synthetic table with strong jumps in all three groups, and 0 with none.
5. Rows outside the exploration half are dropped before anything is computed.
6. `results.json` parses as standard JSON and carries `first_stage.n_strong` and `estimates.finite`. The three figures are written.
7. `uv run ruff check .`, `uv run ruff format --check .` and `uv run pytest` pass.
