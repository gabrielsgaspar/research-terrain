# Task: acquire INEP schools and the school catalogue, and match polling places to schools (build, idea 0006)

## Goal

Three datasets for idea 0006:

- `inep_schools`: school facilities by year, from Base dos Dados on
  BigQuery;
- `inep_school_catalogue`: one recent year of school names, addresses and
  postcodes from INEP's Censo Escolar microdata, with coordinates where
  INEP's school catalogue gives them;
- `school_polling_match`: each polling place matched to an INEP school,
  with a confidence level.

No phone number, email or personal name is ever stored. Campaign
`research/campaigns/0005-geography-of-representation/campaign.md`, step s6.
Steps s7 and s8 run the two acquires and s9 the match build, through
`data-pipeline`.

## Idea

Idea 0006 (`research/ideas/0006-geography-of-representation.md`), decision
0011. The data rules are in `AGENTS.md` ("Data", "Personal identifiers") and
decision 0003. `inep_schools` holds outcome data (facilities) for both
halves. It stays in raw, which no exploration account reads, and only
`place_outcomes` (step s10) reads it. The match reads no facility field. The
model for the BigQuery path is `src/terrain/ibama.py` with
`src/terrain/bigquery.py` (campaign 0004, step s1). This is a **build** task:
it may change exactly the files below.

### Rules that bind this code

- **No URL or raw folder in code** (`tests/test_acquire.py::test_no_url_or_dataset_folder_in_code`).
  Every URL, endpoint, scope and table id lives in the catalog.
- **Identifiers and contact data.** These are never selected, read, stored,
  logged or put in a manifest:
  - BigQuery: `telefone`, any column starting with `nome` (refused by
    `bigquery._identifier`, unchanged);
  - microdata: `NU_DDD`, `NU_TELEFONE`, and any column whose name contains
    `EMAIL`. INEP's 2024 file has no email column.
  
  The school name (`NO_ENTIDADE`) is the name of a public building, not of
  a person. It is read from the microdata only.
- **Encodings:** every text read or write names its encoding.
- **Write-once raw:** new dated folder (`terrain.acquire._free_prefix`); the
  manifest is the last object created; nothing is uploaded until every check
  passes.
- **TLS for INEP.** `download.inep.gov.br` does not send its intermediate
  certificate, so the system trust store alone fails ("unable to get local
  issuer certificate"; checked 2026-11-10). The certificate is pinned in
  `data/reference/certs/rnp_icpedu_gr46_ov_tls_ca_2025.der.b64` (base64 of
  the DER bytes; see `data/reference/certs/README.md`). The download builds
  its own `ssl.create_default_context()` (system store) and adds the pin with
  `load_verify_locations(cadata=<DER bytes>)`, after checking that the bytes
  hash to the SHA-256 in the catalog. Verification is never turned off, and
  `ssl.VERIFY_X509_PARTIAL_CHAIN` is never set. Use `urllib.request` with
  that context, in `src/terrain/inep.py`; `terrain.http` is unchanged.
- **Tests** never touch the network, GCS or BigQuery.

### `bigquery.py` changes

- `_where`: `years` may be absent or `null`; then the year clause is left
  out. `states` stays required.
- `build_summary_query`: a block may set `freshness_column` (for example
  `data_extracao`). When it is absent the query is
  `SELECT COUNT(*) AS n FROM ... WHERE ...`. Existing blocks keep their
  behaviour: the IBAMA entries gain `freshness_column: data_extracao` in
  this task's catalog change, so their query text is unchanged. Check this
  with a test.

### Acquire `inep_schools`

- BigQuery path only, as in `ibama.py`: credentials, session, billing project
  from `GOOGLE_CLOUD_PROJECT`, paging, typing and the failure rules.
- Unchanged check: the summary query (`COUNT(*)`; no freshness column). If
  the latest manifest has the same query text and the same count, return
  `unchanged`.
- Store one Parquet, `inep_schools.parquet`, typed:
  - `ano` Int64;
  - `id_escola`, `id_municipio`, `sigla_uf`, `rede`, `tipo_localizacao`
    Utf8;
  - each facility column Int8, null kept.
  
  Values are stored as received, with no recoding. Size check: 2 GB.
- Manifest notes: rows per year; for each facility column, the years in
  which it is entirely null; the distinct values of `rede` and
  `tipo_localizacao`. Values only.

### Acquire `inep_school_catalogue`

- Download the zip with the pinned context. Check that it is a zip with
  exactly one member matching `member`.
- Stream the member (Latin-1) to a temporary UTF-8 file in chunks. Read it
  with `pl.scan_csv(..., separator=";", infer_schema=False)`, selecting only
  the listed columns. Check that every listed column is in the header. The
  phone columns are never selected, and a test checks that their synthetic
  values reach no output.
- Run the BigQuery coordinates query. A failure there fails the run: the
  match needs to know which schools have coordinates.
- Store one Parquet, `inep_school_catalogue.parquet`, one row per
  `CO_ENTIDADE`. Columns:
  - `ano` (Int64), `id_escola` (Utf8, from `CO_ENTIDADE`), `nome_escola`
    (Utf8, from `NO_ENTIDADE`), `id_municipio` (Utf8, 7 digits), `sigla_uf`;
  - `rede` (Utf8, `TP_DEPENDENCIA`), `tipo_localizacao` (Utf8);
  - `endereco`, `numero`, `complemento`, `bairro` (Utf8);
  - `cep` (Utf8, 8 digits with leading zeros, or null when not 1-8 digits);
  - `latitude`, `longitude` (Float64 from Base dos Dados, joined on
    `id_escola`; null when absent, 0, or outside latitude -34..6 and
    longitude -74..-28).
  
  The column `nome_escola` is a school's name, so `bigquery._identifier`'s
  `nome` guard does not apply (that guard is for BigQuery column names, and
  this column comes from the microdata).
- Manifest notes: rows; rows per state; share with a CEP; share with
  coordinates; microdata rows with no coordinate row and coordinate rows
  with no microdata row (counts). Values only.

### Build `school_polling_match`

Inputs: the national `polling_places` (step s4; columns in
`data/contracts/polling_places.md`, including `nr_cep` from step s1) and
`inep_school_catalogue`. One output Parquet per election year 2008, 2012,
2016, 2020 and 2024: `school_polling_match_<year>.parquet`.

**Normalising text** (`normalise`): upper case; accents removed (NFKD);
every character that is not a letter or digit becomes a space; single
spaces. For names, also drop every one-letter token and these tokens:
`ESCOLA ESC EMEF EMEI EMEB EMEIEF EEEF EEEFM EE EM EEM EF MUNICIPAL MUN ESTADUAL EST COLEGIO COL UNIDADE
ESCOLAR UE CENTRO EDUCACIONAL CE INSTITUTO DE DA DO DAS DOS ENSINO
FUNDAMENTAL MEDIO INFANTIL BASICA E PROF PROFA PROFESSOR PROFESSORA DR DRA
DONA DOM`. An address is `endereco` plus `numero` (school) or `ds_endereco`
(polling place), normalised with no tokens dropped.

**Scores** for each pair (polling place, school in the same `cd_ibge` =
`id_municipio`):

- `name_sim`: `difflib.SequenceMatcher(None, a, b).ratio()` of the
  normalised names; 0 when either is empty.
- `addr_sim`: the same on the normalised addresses.
- `cep_equal`: both CEPs present and equal.
- `dist_km`: great-circle distance between the polling place's `lat`/`long`
  and the school's coordinates, when both exist; otherwise null.
  `near` = `dist_km` ≤ 1.

**Confidence** of a pair:

- `high`: `name_sim` ≥ 0.90 and (`cep_equal` or `addr_sim` ≥ 0.80 or `near`);
- `medium`: not high, and either `name_sim` ≥ 0.90, or `name_sim` ≥ 0.75 and
  (`cep_equal` or `near`);
- `low`: neither, and `name_sim` ≥ 0.60;
- otherwise no match.

Each polling place keeps its best school, ordered by confidence (high,
medium, low), then `name_sim`, `addr_sim`, smaller `dist_km` (null last),
then `id_escola`. A place with no pair above `low` keeps one row with
null school and `confidence` `none`. These rules and thresholds are fixed
here, before any real match is run; changing them needs a new task.

**Output columns:** the polling-place key (`ano`, `cd_ibge`, `sg_ue`,
`nr_zona`, `nr_local_votacao`), `id_escola`, `rede` (from the catalogue),
`confidence`, `name_sim`, `addr_sim`, `cep_equal`, `dist_km`, and
`n_candidates` (schools in the municipality with `name_sim` ≥ 0.60). Names
and addresses are not copied to the output.

**Manifest notes:** per year, places, and the share at each confidence
level overall and by state (`match_rate high+medium` by state and year, as
Gabriel asked); places sharing one school (count). Matching is not an
outcome, so the notes may cover both halves.

**Output path:** `content_hash` of the input SHA-256s, the years and the
code of the build and of every `terrain` module it imports.
