# Task: what amendments buy, by share and log reais: first stage of the powered outcomes and reduced form in close mayoral races (explore, idea 0010)

## Goal

A new explore script, `explore/0010_amendments_main.py`, on the
exploration half. It estimates idea 0010's first stage, only for the
outcomes that step s4's gate run found powered, and the reduced form, with
the secondary analyses declared in the campaign. Its `results.json` carries
`first_stage.n_strong` and `estimates.finite`, the fields step s6's kill
rules read. Campaign
`research/campaigns/0011-amendments-share-of-quota/campaign.md`, step s5.
Step s6 runs it through `explore-run`.

## Idea

Idea 0010 (`research/ideas/0010-amendments-share-of-quota.md`); decisions
0003, 0008 and 0011. This draft follows campaign 0009's `drafts/s8.md`
(never built), with the outcomes of idea 0010.

Step s3's script, `explore/0010_amendments_gate.py`, holds the outcomes
(`OUTCOMES`), and through 0009's `explore/0009_amendments_gate.py` the

the two files below.

### Rules that bind this script

- **Exploration half, national:** `exploration_municipalities(store,
  national=True)`, then `restrict` on `cd_ibge` before anything else.
- **Data read (referee R2).** Only `amendments_panel` (derived), `panel_A`,
  `panel_B` and `panel_C`, found as s3's script finds them. The outcomes
  are the point of this step and the campaign lists them:
  - payments in the post window (January m+1 to September m+2):
    `amend_post_share`, `amend_post_log_pc` and, for the votes-per-real
    ratio only, `amend_post_total`;
  - votes at t1 = 2018, 2022 and 2026: `votes_t0`, `votes_t1`, `d_share`,
    `ran_t1`.

  Plus s3's `READ_COLUMNS`. Nothing in `sealed/`.
- **The gate's run record (read by code, not by a person).** Which outcomes
  are estimated comes from s4's run record, never from a constant:
  - In `research/explore-runs/0010/`, the records `<run id>.md` whose first
    line starts with `# 0010_amendments_gate, run ` and that have a
    `<run id>.json` beside them. Fork records are named after other scripts
    (`*_fN`) and so are never taken.
  - Take the one with the largest run id. If there is none, raise.
  - Powered outcomes: each `<o>` in s3's `OUTCOMES` with
    `power.outcomes.<o>.powered` equal to 1, in that order. If none, raise:
    s4 would have stopped the campaign.
  - Expose this as `gate_record(directory: Path) -> dict` returning the run
    id, the record's `window.h_pct` and the list of powered outcomes.
- **h:** `choose_window` as in s3. If it finds no window, raise. If its
  `h_pct` differs from the record's `window.h_pct`, raise: the data changed
  since the gate.
- **Nothing beyond this issue (referee R7):** exactly the estimates below,
  at h and at 5%; no other window, outcome or subgroup. An outcome the
  record marks unpowered is never estimated.
- **Compute:** as s3's script.

### The design (fixed)

- **Units, model, draws and inference** as in s3's script:
  - Y = b·win + g·margin + d·win·margin + deputy-by-cycle fixed effects, on
    |margin| ≤ w;
  - standard errors clustered by `cd_ibge`;
  - race re-flips, 2,000 draws, seed 20261115;
  - `ri_p` = (1 + #{|b_draw| ≥ |b|}) / 2001.
- **Alpha 0.025 for each test** (two-sided; two outcomes). For every b
  report the 97.5% interval b ± 2.2414 × se (`ci_low`, `ci_high`), and
  `ri_p`.
- **First stage (kill rule k1),** for each powered outcome `<o>`:
  - `share`: Y = `amend_post_share`; `log_pc`: Y = `amend_post_log_pc`.
    Units with a null Y leave that fit only.
  - b, se, `ci_low`, `ci_high`, `ri_p`, the mean of Y, the units and
    races in the fit;
  - `f_cluster` = (b / se)²; `strong` = 1 if `f_cluster` ≥ 10, else 0.
  - `first_stage.n_strong` = the number of powered outcomes with
    `strong` 1.
- **Reduced form:** Y = `d_share` (the change in the deputy's vote share
  in the municipality, t1 minus t0), on units with `ran_t1` true. b, se,
  `ci_low`, `ci_high`, `ri_p`, the mean, the units, and the count of units
  with `ran_t1` false. Estimated once (it does not depend on the money
  outcome).
- **By cycle (secondary):**
  - the model with `win`, `margin` and `win·margin` each interacted with
    cycle dummies (deputies are already cycle-specific);
  - b for cycles A, B and C, for each powered first stage and for the
    reduced form;
  - the C-minus-A difference with its clustered SE.
- **Votes per real (secondary; an upper bound, because allied mayors also
  campaign):**
  - b of Y = `votes_t1` − `votes_t0` (units with `ran_t1`) divided by b of
    Y = `amend_post_total` (reais, all units);
  - times 1,000: votes per 1,000 reais.
  - Report it, its two parts and the label "upper bound" in `summary.md`.
    No standard error, no test.
- **At 5%:** the first stage of each powered outcome and the reduced form;
  reported only.

### `results.json` keys (exact; no dots inside a key)

- `gate.run_id`, `gate.h_pct`, `gate.powered` (list of outcome names),
  `window.h_pct`.
- `first_stage.n_strong` (int, **k1**); for each powered `<o>`:
  `first_stage.outcomes.<o>.f_cluster`, `.strong`, `.b`, `.se`, `.ci_low`,
  `.ci_high`, `.ri_p`, `.mean`, `.n_units`, `.n_races`. An unpowered
  outcome has no key under `first_stage.outcomes`.
- `reduced_form.b`, `.se`, `.ci_low`, `.ci_high`, `.ri_p`, `.mean`,
  `.n_units`, `.n_not_running`.
- `by_cycle.first_stage.<o>.<A|B|C>.b` and `.se`;
  `by_cycle.first_stage.<o>.c_minus_a.b` and `.se`; the same under
  `by_cycle.reduced_form` (without `<o>`).
- `wald.votes_per_1000_reais`, `wald.rf_votes_b`, `wald.fs_reais_b`.
- `at_5pct.first_stage.<o>.f_cluster`, `.b`, `.se`, `.ri_p`;
  `at_5pct.reduced_form.b`, `.se`, `.ri_p`.
- `estimates.finite` (bool, **k2**): true only if every number above was
  finite when computed.

Non-finite numbers are written as `null` and set `estimates.finite` to
false. `first_stage.n_strong` is never null: if a powered outcome's
`f_cluster` cannot be computed, raise.

`summary.md`:

- which gate record was read (run id) and the powered outcomes;
- one table: estimate, b, SE, 97.5% interval, RI p, mean, at h and at 5%;
- the by-cycle table;
- the votes-per-real ratio, labelled an upper bound;
- a line that the outcomes were chosen after campaign 0010's gate failed
  on per-capita reais;
- a line that nothing on the exploration half is a finding.

## Out of scope

- Unpowered outcomes, per-capita reais as a first stage (it enters only
  the votes-per-real ratio), coalitions or federations, state deputies,
  Pix-only samples, the extensive margin, any window other than h and 5%,
  the confirmation half.

## Done when

1. A synthetic panel built in the test recovers planted effects within 10%:
   - three cycles, 300 races;
   - a planted jump in `amend_post_share`, one in `amend_post_log_pc` and
     a planted reduced-form jump;
   - `f_cluster` above 10 with the jump, and RI p above 0.05 for a null
     outcome with the fixed seed.
2. `gate_record` on a temporary directory:
   - with two gate records, takes the larger run id;
   - ignores a fork record (`# 0010_amendments_gate_f1, run ...`) and a
     record without its `.json`;
   - raises with no record, and with no powered outcome.
3. With only `log_pc` powered in the record, `share` is not estimated (no
   key under `first_stage.outcomes`) and `n_strong` counts `log_pc` only.
4. An `h_pct` in the record that differs from `choose_window`'s raises.
5. The by-cycle C-minus-A difference matches the difference of the planted
   cycle effects within 10%.
6. Units with `ran_t1` false are excluded from the reduced form and
   counted.
7. `results.json` has `first_stage.n_strong` as a number and
   `estimates.finite`, and parses as standard JSON.
8. Rows outside the exploration half are dropped before estimation (test).
9. `uv run ruff check .`, `uv run ruff format --check .` and `uv run pytest`
   pass.
