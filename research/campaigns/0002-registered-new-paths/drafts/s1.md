# Task: check the registered analysis's new paths on real data, without estimates (explore, idea 0001)

## Goal

Run 42476480500 (issue #241) showed that idea 0001's registered analysis
(`src/terrain/registered/r0001/analysis.py`) reproduces every number of the
explore runs it was frozen from. It did not check the parts that are new in
the plan, because no earlier run has them: the incumbency-adjusted estimates
(`direct_adj`, `ring2_adj`, `ring5_adj`, `direct_pre_adj`, built from Z), the
direct placebo (`direct_pre`), the alignment split (`align`) and the balance
table (`balance`).

This task writes a script that checks those paths on the exploration half at
the 0.50% window and reports only structural facts: counts of pairs and
cells, and pass or fail for each check. **It reports no slope, RI p, p1,
quantile, clustered SE, mean or percentage of any estimate.** It is a check
of the code on real data before registration, not a result.

Campaign `research/campaigns/0002-registered-new-paths/campaign.md`, step s1.
Step s2 runs the script once through `explore-run`; its kill rules read the
keys listed under "What `results.json` holds".

### What runs

`uv run python explore/0001_registered_paths_check.py --out-dir DIR`, through
`explore-run` with `script=0001_registered_paths_check`. It calls
`exploration_municipalities` and `restrict` like every explore script. It
reads through the analysis's own `Reader`, built as `run_exploration` builds
it, with the real treatment, on the exploration half, at window 0.005 only.
It may call the module's functions (`treatment_year`, `incumbent_sign`,
`z_terms`, `align_components`, `outcome_year`, `balance_differences`) one
election at a time, where `run` does not return the parts a check needs.

Calling those functions directly bypasses `run_exploration`'s refusal of the
registered window, so the script refuses it itself: the window is a constant
0.005, and the function that runs the checks raises if it is given a window
within 1e-12 of `analysis.REGISTERED_WINDOW` (0.0025).

**Outcome data in scope (referee R2):** `cell_outcomes` of the exploration
half, the years each election reads in run 42298466207 (E-4 .. E-1 and
E+1 .. E+4, never E; for 2024, E-4 .. E-1 only). Outcomes are read only
because the analysis builds its samples from them; no outcome value or
estimate is reported. The script computes nothing beyond the checks below
(referee R7).

### The checks (each pass or fail, with counts where named)

1. **Pairs with exactly one incumbent (Z).** Per election 2008-2020 and
   pooled, the number of close pairs with `s = +1` (only the winner held the
   seat), `s = -1` (only the loser did) and `s = 0` (both, neither or
   unknown), from `incumbent_sign`. Pass if `+1` and `-1` sum to more than
   zero in every election.
2. **The same pairs and cells with and without Z.** For `direct`, `ring2`,
   `ring5` and `direct_pre`, the adjusted part uses the same sample cells
   (same rows, same order) as the unadjusted one. Every Z pair term is `s`
   times that pair's D term, and the Z pairs are a subset of the D pairs.
   Report the number of cells with a non-zero Z per exposure and election.
3. **Z is fixed under re-flips.** For one re-flip draw (seed 20261106,
   draw 1), swapping every flipped pair's sides leaves every Z term
   unchanged, while the D terms of flipped pairs change sign. Pass or fail
   only.
4. **The alignment split adds up.** Per election, the counts of `aligned`,
   `unaligned`, `mixed` and `left_out` pairs sum to the pairs. Per
   (cell, pair), the alignment components' terms sum to the D term exactly.
   Report the counts per kind and the pairs per election.
5. **The direct placebo uses the direct exposure.** `direct_pre`'s terms are
   `direct`'s terms, and its sample cells are the direct cells that have
   every pre-election year. Pass or fail, plus the number of cells per
   election.
6. **No NaN or infinite values.** Every number the analysis returns for
   `direct_adj`, `ring2_adj`, `ring5_adj`, `direct_pre`, `direct_pre_adj`,
   `align` and `balance` is finite, or is an explicit null that the analysis
   documents (a non-estimable slot). Report the dotted paths of any
   non-finite values, never the values.
7. **Balance is computed on every covariate.** Every covariate of
   `fz.BALANCE` has a winner-minus-loser difference for every election the
   balance table reads (2008-2024), and the omnibus p exists. Pass or fail
   only. The table is not printed.

### What `results.json` holds

Written with `write_results`. Keys never contain dots; elections are keyed
`e2008` .. `e2024`.

- `checks.c1` .. `checks.c7`, each with `pass` (a JSON boolean, `true` or
  `false`, never a string or null) and `counts` (an object, empty for checks
  3 and 7).
- `checks.c1.counts.e<year>.plus`, `.minus`, `.zero` for 2008-2020, and
  `checks.c1.counts.pooled.plus`, `.minus`, `.zero` and
  `.one_incumbent` (plus + minus, pooled 2008-2020).
- `checks.c2.counts.<exposure>.e<year>`: cells with a non-zero Z, for
  `direct`, `ring2`, `ring5`, `direct_pre`.
- `checks.c4.counts.e<year>`: `aligned`, `unaligned`, `mixed`, `left_out`,
  `pairs`.
- `checks.c5.counts.e<year>`: cells in the `direct_pre` sample.
- `checks.c6.counts.nonfinite` (a whole number) and `checks.c6.paths` (a
  list of dotted paths, at most 100).
- `n_checks` (7), `n_fail` (whole number), `all_pass` (boolean), `window`
  (the text `"0.50%"`, not a number).

The kill rules of step s2 read `checks.c1.pass` .. `checks.c7.pass` (each
kills the step unless it is `true`) and `checks.c1.counts.pooled.one_incumbent`
(kills the step below 200). Each must be written at exactly that path.

`summary.md`: the first line is "Structural checks: pass" or "Structural
checks: fail (N of 7)". Then one row per check, with pass or fail and the
counts named above, and then the caveats: exploration half only; 0.50% is
not the registered window; this checks code paths, not estimates.

### Never

- Any run at 0.25%.
- Any estimate, p-value or quantile in `summary.md`, `results.json`, logs or
  exception messages. A failed check reports where it failed (election,
  exposure, path), never the numbers that differ.
- Any read of `sealed/` or `confirm/`.
- Changing the frozen code to make a check pass.

## Out of scope

- Every other file, including the idea file and `research/lessons.md`
  (inside a campaign the tracking issue's ledger stands in for both until the
  close-out).
- Any other window, any estimate, any comparison with earlier runs' numbers.
