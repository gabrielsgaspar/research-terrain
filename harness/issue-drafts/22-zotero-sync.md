# Task: `zotero_sync`: generate `refs.bib` and reference-note stubs from the Zotero library

## Goal

Build plan 3.2. A script reads the curated `terrain` Zotero group library
(read-only key) and writes `research/references/refs.bib`, plus one note
stub `research/references/<citekey>.md` for each item tagged `core` that has
no note yet. The `zotero-sync` workflow (written separately by a person)
runs it and opens a PR with what changed.

## Idea

Infrastructure. Read `harness/BUILD_PLAN.md` section 4.2 (ownership, note
template) and `research/references/README.md` first. Decision (Gabriel,
2026-11-04): `refs.bib` is generated in this repository, at
`research/references/refs.bib`.

## The Zotero Web API (version 3)

- Items: `GET https://api.zotero.org/groups/<group>/items/top?format=json&include=data,bibtex&limit=100&start=<n>`
  with headers `Zotero-API-Key: <key>` and `Zotero-API-Version: 3`. The body
  is a JSON array; the `Total-Results` header gives the count, so page with
  `start` until it is reached. Each element has `key` (the Zotero item key),
  `data` (`itemType`, `title`, `DOI`, `tags` as a list of `{"tag": ...}`,
  `extra`, and, in recent schemas, `citationKey`) and `bibtex` (one BibTeX
  entry as text).
- `items/top` excludes child items; skip any `itemType` of `attachment`,
  `note` or `annotation` anyway.
- The group libraries are private: without the key the API answers 403.
  The key comes only from the environment (`ZOTERO_READ_KEY`), the group
  from `ZOTERO_GROUP_ID`; neither is ever printed or written.

## Rules

1. **Citation key** (Better BibTeX keys are pinned, build plan 3.1): the
   item's `data.citationKey` when non-empty; otherwise a line `Citation Key:
   <key>` in `data.extra` (case-insensitive, Better BibTeX's pinned form);
   otherwise the item is **unkeyed**: left out of `refs.bib` and listed by
   Zotero key and title in the report. A key must match
   `^[A-Za-z0-9_:\-.]+$`; two items with the same key stop the sync.
2. **`refs.bib`:** a first line `% Generated by scripts/zotero_sync.py from the
   Zotero library; do not edit.`, then every keyed item's `bibtex` with the
   entry's own key (the text between the first `{` and the first `,`)
   replaced by the citation key, entries sorted by key, one blank line
   between them, LF line endings, UTF-8. The same library gives the same
   bytes.
3. **Stubs:** for each keyed item with the tag `core` and no existing file
   `research/references/<citekey>.md`, write the note template of build plan
   4.2: front matter `citekey`, `doi` (`data.DOI`, or empty), `zotero_key`,
   `status: core`, `role` (the first of the tags `closest`, `adjacent`,
   `method`, or empty), `strands: []`, `links: []`; then the six headings with
   their comments, exactly as in the plan. An existing note is never
   touched.
4. **Report:** the script prints one JSON object: items read, keyed,
   unkeyed (list of Zotero key and title), entries in `refs.bib`, stubs
   written (list of citekeys). Titles are bibliographic metadata, safe to
   print.

## In scope

- `src/terrain/zotero.py`: `fetch_items(get, group, key)` (paging through an
  injected `get(url, headers) -> (headers, body)` callable, so tests need no
  network), `citation_key(item)`, `render_bib(items)`, `stub(item)` and
  `sync(items, references_dir) -> report`.
- `scripts/zotero_sync.py`: thin script; `--references-dir` (default
  `research/references`), a `urllib` `get` with a 60 s timeout, reads the
  two environment variables, writes the files, prints the report.
- `tests/test_zotero.py`.

Expected files (three): `src/terrain/zotero.py`, `scripts/zotero_sync.py`,
`tests/test_zotero.py`.

## Out of scope

The workflow (`.github/workflows/zotero-sync.yml`, a person's change),
`research/references/README.md`, `pyproject.toml`, `uv.lock`, any other
record.

## Done when

1. With a fake `get` serving 230 items in pages of 100, `fetch_items`
   requests `start` = 0, 100, 200 and returns 230 items; the key goes only in
   the `Zotero-API-Key` header, never in a URL.
2. `citation_key` takes `data.citationKey` first, then `Citation Key: x` in
   `extra` (any case), and returns None otherwise; a key with a space or a
   brace is rejected.
3. `render_bib` replaces each entry's key, sorts by key, starts with the
   header line, and gives identical bytes for the items in any order; two
   items with one key raise.
4. `sync` writes a stub only for `core` items without a note, with the
   front matter and headings of the template, and leaves an existing note
   byte-identical; attachments and notes are skipped; unkeyed items are in
   the report and not in `refs.bib`.
5. No test uses the network; the script contains no key or group id; `uv
   run ruff check .`, `uv run ruff format --check .` and `uv run pytest`
   pass.
